# Схема этажа

Кабинет остаётся сущностью Audience с прежним public_id и сеткой оборудования.
Новое поле room_type принимает educational (учебный) или administrative
(административный). Старые записи и запросы создания получают educational.
Нумерация кабинетов остаётся уникальной внутри корпуса.

## API

- GET /api/v1/offices/{office_id}/floors/{floor}/plan доступен всем.
- PUT по тому же адресу доступен администратору/SU через текущую проверку роли.
- Тип кабинета меняется через существующий API создания/редактирования аудитории.

GET возвращает width, height, revision и rooms: все кабинеты указанного этажа.
У каждого кабинета есть audience_public_id, number, room_type, description
и placement. У неразмещённых кабинетов placement равен null.
Пустая схема имеет размер 20x12 и revision=0; чтение её не создаёт.
Можно заранее сохранить схему пустого этажа существующего корпуса.

landmarks содержит строки north, south, west и east (до 128 символов).
Пустая строка в интерфейсе заменяется названием стороны света. Подписи
сохраняются вместе с геометрией и защищены той же revision. Старые клиенты,
не отправляющие landmarks, не стирают ориентиры; landmarks={} очищает их.

landmarks содержит строки north, south, west и east (до 128 символов).
Пустая строка в интерфейсе заменяется названием стороны света. Подписи
сохраняются вместе с геометрией и защищены той же revision. Старые клиенты,
не отправляющие landmarks, не стирают ориентиры; landmarks={} очищает их.

Пример PUT (UUID нужно заменить на UUID кабинета этого этажа):

```json
{
  "revision": 0,
  "width": 20,
  "height": 12,
  "rooms": [
    {
      "audience_public_id": "019d86cc-4318-7d61-a834-999f8562b448",
      "x": 0, "y": 0, "width": 3, "height": 2
    }
  ]
}
```

Координаты целочисленные, начинаются с нуля. Максимум 50x50 клеток и 400
размещённых кабинетов. Прямоугольники не пересекаются и не выходят за границы.
PUT заменяет все позиции: исключённый кабинет становится неразмещённым,
но не удаляется вместе с оборудованием.

revision из последнего GET обязателен. При устаревшей версии сервер возвращает
409; клиент должен перечитать схему, а не молча перезаписывать чужую работу.
Неизвестный UUID или кабинет другого этажа/корпуса приводит к 400,
невалидная геометрия к 422. Удаление или перенос кабинета очищает его позицию
и увеличивает revision затронутых схем в той же транзакции.

Схема принадлежит inventory. Позиции в JSONB ссылаются на UUID кабинетов,
а названия и типы читаются из Audience, без копирования оборудования.
Сохранение и аудит выполняются в общей транзакции; в аудит попадают размеры,
этаж, количество кабинетов и revision, но не полный массив координат.

## Интерфейс

В заголовке каждого этажа на странице корпуса есть ссылка «Схема этажа».
Она открывает отдельную страницу `/Office/:officeNumber/floors/:floorNumber`.
На странице корпуса остаются только карточки и список. Старые ссылки
`?view=plan&floor=N` перенаправляются на новый маршрут.
На схеме можно переключать этажи, искать кабинеты и открывать сведения об этаже.
Просмотр и переход к оборудованию по UUID доступны гостям. Администратор редактирует расположение кабинетов
перетаскиванием, стрелками клавиатуры или полями координат и размера.
В интерфейсе координаты начинаются с единицы, в API остаются нулевыми.

Кабинеты без позиции показаны под схемой. В редакторе можно выбрать кабинет
и нажать на свободное место либо разместить его автоматически. «Снять с плана»
убирает только позицию. Тип кабинета выбирается в форме создания/редактирования.
Административный кабинет можно создать без оборудования.
Поиск выделяет совпадения и приглушает остальные кабинеты, не удаляя позиции
и не размонтируя редактор.

Сохранение явное; без изменений запрос не отправляется. Ошибка сети и 409
сохраняют черновик на странице. После 409 требуется явная загрузка актуальной
версии. Переход на другую страницу или этаж и обновление вкладки предупреждают
о несохранённых изменениях. Черновики не сохраняются между перезапусками браузера.

Переход в кабинет передаёт источник, этаж и поиск через
`officeView` / `officeFloor` / `officeSearch` в query. Кнопка «К схеме этажа»
возвращает на отдельную страницу, а «К списку аудиторий» возвращает в корпус.
Контекст сохраняется при обновлении вкладки аудитории и переходе в её редактор.
Для прямой ссылки без контекста открываются карточки корпуса и этаж аудитории.
Поиск и положение прокрутки сетки и страницы хранятся в sessionStorage
для последних 20 этажей. Черновики и данные оборудования туда не копируются.

Пока схема обновляется по кнопке «Обновить» или при новом открытии.
Следующий этап: SSE-сигнал изменения схемы с уведомлением о чужих правках,
без замены открытого черновика. Текущие события оборудования не менялись.

Перед запуском backend применить миграцию: uv run alembic upgrade head.
Миграция не меняет существующие координаты оборудования.
